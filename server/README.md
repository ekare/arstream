# arstream-server

The reference receiver that speaks `docs/PROTOCOL.md`: the phone connects to this server over TCP and sends its video+metadata stream. The server runs two things at once, in the same process:

1. **Ingest server** — the raw protocol socket, where the mobile client connects (default port `9999`).
2. **Web dashboard** — live session monitoring, downloading past recordings as `.zip` (default port `8080`).

This package is **not a production ingestion service** — it's a working reference implementation of the protocol plus its living documentation. If an external "adapter" is going to actually consume the stream, it reads `docs/PROTOCOL.md`; it may copy this server as a starting point if it wants to.

## Installation

Requires Python **3.11+**.

```bash
cd server
pip install -e ".[dev]"
```

Without `[dev]` (`pip install -e .`) only the runtime dependencies are installed; `[dev]` is needed for tests/development.

There are also convenience scripts under `scripts/` that create a virtual environment and install into it — see [Install/start/stop scripts](#installstartstop-scripts) below.

### Dependencies and why

| Package | Why |
|---|---|
| `fastapi` | The dashboard's web framework. Automatic OpenAPI/`/docs` page, native `WebSocket` support, `asyncio`-native — runs in the same event loop as the ingest server, no separate thread/process needed. |
| `uvicorn[standard]` | The ASGI server that runs FastAPI. The `[standard]` extra pulls in `websockets` (the WebSocket implementation) and `httptools`. |
| `pytest`, `pytest-asyncio` *(dev)* | Test framework; `pytest-asyncio` lets `async def test_...` functions run directly (`asyncio_mode` is configured in `pyproject.toml`). |
| `httpx` *(dev)* | The underlying transport for `starlette.testclient.TestClient` — used to test the dashboard's HTTP/WebSocket endpoints without opening a real socket. |
| `av` *(optional, `[video]`)* | PyAV — for decoding the recorded Annex-B H.264 into frames, if desired (no built-in plugin does this yet; reserved for future analysis plugins). |

No other external dependencies — `arstream_server.protocol` needs nothing beyond stdlib `struct`+`json` (see the note at the top of the source file).

## Running

```bash
arstream-server --host 0.0.0.0 --port 9999 --web-host 0.0.0.0 --web-port 8080 --out ./captures
```

or as a module: `python -m arstream_server.cli` (same arguments).

| Argument | Default | Meaning |
|---|---|---|
| `--host` | `0.0.0.0` | Address the ingest (TCP) server listens on — the phone connects here |
| `--port` | `9999` | Ingest server port |
| `--web-host` | `0.0.0.0` | Address the dashboard listens on |
| `--web-port` | `8080` | Dashboard port — reach it from a browser at `http://<machine-ip>:8080` |
| `--out` | `./captures` | Directory recordings are written to (`captures/<session_id>/video.h264`, `frames.jsonl`, `imu.jsonl`, `poses.jsonl`, `points.jsonl`, `intrinsics.json`, `meta.json` — see [Recorded files](#recorded-files)) |
| `--plugins-dir` | (none) | Directory containing additional external plugins — see [Writing a plugin](#writing-a-plugin) |

On startup:
- Dashboard: `http://<host>:8080/`
- Automatic API documentation (generated by FastAPI): `http://<host>:8080/docs`

## Install/start/stop scripts

`scripts/` has cross-platform convenience scripts for setup and for running the server as a background process:

| Script | Platform | Does |
|---|---|---|
| `install.sh` / `install.ps1` | Linux/macOS / Windows | Creates a `.venv` (if missing) and runs `pip install -e .`. Pass `--dev` (`.sh`) or `-Dev` (`.ps1`) to install with the `[dev]` extras instead. |
| `start.sh` / `start.ps1` | Linux/macOS / Windows | Starts `arstream-server` in the background (preferring the `.venv` created by `install`, falling back to `PATH`), writes its PID to `arstream-server.pid`, and redirects output to `arstream-server.log`. Any extra arguments are passed straight through to `arstream-server`. Refuses to start a second instance while a PID file for a live process already exists. |
| `stop.sh` / `stop.ps1` | Linux/macOS / Windows | Reads `arstream-server.pid`, sends a graceful stop signal, waits up to ~10s, then force-kills if it hasn't exited. Removes the PID file. |

```bash
# Linux/macOS
cd server
./scripts/install.sh --dev
./scripts/start.sh --out ./captures
./scripts/stop.sh
```

```powershell
# Windows
cd server
.\scripts\install.ps1 -Dev
.\scripts\start.ps1 --out .\captures
.\scripts\stop.ps1
```

The PID file, log file, and venv locations can be overridden with the `ARSTREAM_PID_FILE`, `ARSTREAM_LOG_FILE`, and `ARSTREAM_VENV` environment variables if you need to run more than one instance or fit a different directory layout.

## API endpoints

| Endpoint | Kind | Returns |
|---|---|---|
| `GET /` | HTTP | The dashboard HTML page |
| `GET /api/sessions` | HTTP | `{"sessions": [...]}` — all sessions (live + past), with their latest state |
| `GET /api/sessions/{id}` | HTTP | A single session's detail, `404` if not found |
| `GET /api/sessions/{id}/download` | HTTP | A `.zip` of `captures/<id>/`'s entire contents (see [Recorded files](#recorded-files)), packaged on the fly in memory (no `.zip` is written to disk) |
| `WS /ws/live` | WebSocket | `{"type": "session_start"\|"session_update"\|"session_end", "session": {...}}` events — the dashboard's live tables listen to this |

## Architecture — why plugin-based

The ingest server (`ingest.py`) decodes the protocol but does **nothing** with the incoming data itself — it dispatches every event (`session_start`, `video_config`, `video_chunk`, `imu_batch`, `pose_sample`, `point_cloud`, `camera_intrinsics`, `session_end`) to a `PluginManager`. Two built-in plugins consume this:

- **`RecorderPlugin`** (`plugins/recorder.py`) — writes each session to disk. See [Recorded files](#recorded-files) below.
- **`StatsPlugin`** (`plugins/stats.py`) — updates frame/byte counters and publishes periodic events to the dashboard's WebSocket via `EventBus` (every 15 frames, plus `session_start`/`session_end`).

An exception raised by one plugin never stops the other plugins or the ingest itself — `PluginManager` wraps every call in its own `try/except`, logs the error, and keeps the stream going.

### Recorded files

`RecorderPlugin` writes each session to `captures/<session_id>/`. Nothing is muxed into the video bitstream — every file shares the phone's raw device-clock (`timestamp_ns`) domain, so they can be correlated by timestamp (see `docs/PROTOCOL.md` §0):

| File | Format | Contents |
|---|---|---|
| `video.h264` | raw Annex-B | SPS/PPS + frames, concatenated in wire order |
| `frames.jsonl` | JSON lines | one line per `VIDEO_CHUNK`: `{timestamp_ns, is_keyframe, byte_offset, size}` — `byte_offset`/`size` index into `video.h264`, so a specific frame's bytes can be sliced out without decoding the whole stream |
| `imu.jsonl` | JSON lines | one line per sensor sample (batches are flattened): `{sensor_type, timestamp_ns, x, y, z, w}` — see `docs/PROTOCOL.md` §3.4 for what `sensor_type` can be (not just accelerometer/gyroscope) and what `w` (quaternion scalar, rotation-vector-family sensors only) means |
| `poses.jsonl` | JSON lines | one line per `POSE_SAMPLE` (ARCore only): `{timestamp_ns, tracking_state, x, y, z, qx, qy, qz, qw}` |
| `points.jsonl` | JSON lines | one line per `POINT_CLOUD` message (ARCore only): `{timestamp_ns, points: [[x,y,z,confidence], ...]}` |
| `intrinsics.json` | JSON snapshot | latest `CAMERA_INTRINSICS` (ARCore only): `{fx, fy, cx, cy, width, height}` — overwritten on change, not append-only |
| `meta.json` | JSON snapshot | `Session.to_dict()` — same shape as the `/api/sessions/{id}` response |

### Reading a downloaded capture

The `.zip` from `GET /api/sessions/{id}/download` needs no special tooling to consume — every file is either raw Annex-B H.264 or line-delimited JSON, all sharing the phone's device-clock `timestamp_ns` domain so they can be correlated by timestamp alone (`docs/PROTOCOL.md` §0). A minimal worked example — list every keyframe's byte range in `video.h264`, then find the pose closest in time to the first one:

```python
import json
import zipfile

with zipfile.ZipFile("session.zip") as zf:
    video_bytes = zf.read("video.h264")
    frames = [json.loads(line) for line in zf.read("frames.jsonl").decode().splitlines()]
    poses = [json.loads(line) for line in zf.read("poses.jsonl").decode().splitlines()]  # ARCore only, may be empty

keyframes = [f for f in frames if f["is_keyframe"]]
print(f"{len(keyframes)} keyframes out of {len(frames)} frames")

# Slice out the first keyframe's raw NAL bytes without decoding the whole stream:
first_kf = keyframes[0]
nal_bytes = video_bytes[first_kf["byte_offset"] : first_kf["byte_offset"] + first_kf["size"]]

# Nearest pose sample by timestamp (poses.jsonl may be empty if the session used the
# Camera2 fallback backend instead of ARCore -- see docs/DEVICE_COMPATIBILITY.md):
if poses:
    nearest = min(poses, key=lambda p: abs(p["timestamp_ns"] - first_kf["timestamp_ns"]))
    print("pose nearest first keyframe:", nearest)
```

To decode actual pixels instead of just slicing NAL bytes, feed `video.h264` (or the full concatenated stream) to any Annex-B-aware decoder — e.g. PyAV (`av.open("video.h264")`, iterate `container.decode(video=0)`) or `ffmpeg -i video.h264 out.mp4`. `intrinsics.json` (present for ARCore sessions) gives the pinhole camera model (`fx, fy, cx, cy, width, height`) needed to unproject `points.jsonl`'s 3D points or reproject them into the frame.

### Writing a plugin

Subclass `StreamPlugin` (`arstream_server.plugins.StreamPlugin`) and override the callbacks you care about — everything else defaults to a no-op:

```python
# my_plugins/motion_alert.py
from arstream_server.plugins import StreamPlugin
from arstream_server.session import Session


class MotionAlertPlugin(StreamPlugin):
    name = "motion_alert"

    async def on_session_start(self, session: Session) -> None:
        print(f"new session: {session.peer_address}")

    async def on_video_chunk(self, session: Session, timestamp_ns: int, is_keyframe: bool, nal: bytes) -> None:
        if is_keyframe:
            print(f"keyframe arrived: {session.id}, {len(nal)} bytes")

    async def on_session_end(self, session: Session) -> None:
        print(f"session ended: {session.id}, {session.frame_count} frames")
```

Run it:

```bash
arstream-server --plugins-dir ./my_plugins
```

Every `.py` file under `--plugins-dir` (except ones starting with an underscore) is scanned, and any `StreamPlugin` subclasses found inside are instantiated — there's no file-name/class-name convention required. A plugin that throws during `import` is skipped, not fatal to the server.

**Available callbacks** (all `async def`, all optional):

| Callback | When | Parameters |
|---|---|---|
| `on_session_start(session)` | When a new TCP connection opens | `session: Session` |
| `on_video_config(session, config, sps_pps)` | When a `VIDEO_CONFIG` message arrives (once per connection + every reconnect) | `config: dict` (codec/size/fps/rotation), `sps_pps: bytes` (Annex-B) |
| `on_video_chunk(session, timestamp_ns, is_keyframe, nal)` | On every `VIDEO_CHUNK` | `timestamp_ns: int`, `is_keyframe: bool`, `nal: bytes` (Annex-B) |
| `on_imu_batch(session, samples)` | On every `IMU_BATCH` | `samples: list[protocol.ImuSample]` (`sensor_type, timestamp_ns, x, y, z, w`) |
| `on_pose_sample(session, timestamp_ns, tracking_state, x, y, z, qx, qy, qz, qw)` | On every `POSE_SAMPLE` (ARCore only) | all `float` except `timestamp_ns: int`, `tracking_state: int` |
| `on_point_cloud(session, timestamp_ns, points)` | On every `POINT_CLOUD` (ARCore only) | `timestamp_ns: int`, `points: list[protocol.Point]` (`x, y, z, confidence`) |
| `on_camera_intrinsics(session, fx, fy, cx, cy, width, height)` | On every `CAMERA_INTRINSICS` (ARCore only) | `fx, fy, cx, cy: float`, `width, height: int` |
| `on_session_end(session)` | When the connection closes (`session.ended_at` is already set by then) | `session: Session` |

`Session` fields: `id`, `peer_address`, `started_at`, `ended_at`, `video_config`, `rotation_degrees`, `frame_count`, `keyframe_count`, `byte_count`, `fps` — full list in `session.py`.

If you want to publish your own events to the dashboard, inject an `EventBus` into your plugin's `__init__` (this is how the built-in plugins are wired up in `cli.py` — external plugins don't automatically receive a bus right now; to publish your own event type you'll need to edit `cli.py` by hand and pass the `EventBus` into your plugin).

## Testing

```bash
pytest tests/ -v
```

Coverage: protocol golden-byte round-trip (`test_protocol.py`, against `fixtures/*.bin` — the same fixtures used by `mobile/native/tests/protocol_test.cpp`), `EventBus` pub-sub, `PluginManager` dispatch + error isolation + external loading, `RecorderPlugin`/`StatsPlugin` behavior, and the dashboard's HTTP+WebSocket endpoints (via `starlette.testclient.TestClient` — no real socket).

## Directory layout

```
server/
  scripts/
    install.sh / install.ps1     # create a venv + pip install
    start.sh / start.ps1           # start in the background, write a PID file
    stop.sh / stop.ps1               # stop via the PID file
  src/arstream_server/
    protocol.py       # Python mirror of docs/PROTOCOL.md
    session.py         # Session data structure
    events.py           # EventBus (asyncio.Queue-based pub-sub)
    context.py           # AppContext -- state shared by ingest.py + web/app.py
    ingest.py             # TCP ingest server, decodes the protocol and dispatches to PluginManager
    plugins/
      __init__.py          # StreamPlugin base class, PluginManager, load_plugins_from_dir
      recorder.py            # built-in: writes video.h264 + frames/imu/poses/points.jsonl + intrinsics/meta.json
      stats.py                # built-in: counters + WebSocket publishing
    web/
      app.py                  # FastAPI app -- /api/*, /ws/live
      static/dashboard.html     # single-file, no-CDN dashboard UI
    cli.py                       # `arstream-server` entry point
  tests/
```
